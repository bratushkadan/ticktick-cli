# Саммари по TickTick

Запусти `python3 <папка скилла>/scripts/collect.py` с аргументами из таблицы. Сборщик возвращает JSON для ответа пользователю. Даты ниже приведены для примера. По умолчанию используется часовой пояс Europe/Moscow, для другого передай `--timezone`.

| Запрос | Аргументы сборщика |
|---|---|
| Общий день | `digest --day` или `digest --day 2026-11-16` |
| Неделя по двум названным проектам | `digest 2026-11-22 --week --projects 'Work,Digital Infrastructure'` |
| Общий день, неделя по моему настроенному рабочему набору и привычки за 14 дней | `digest --day 2026-11-22 --week --require-work-config --habits 14` |
| Привычки за календарный октябрь | `habits --month 2026-10` |
| Исторический день с подробной проверкой причин отмены | `digest --day 2026-11-16 --format full` |

Для обычного отчёта возьми JSON из stdout. При запуске через `exec_command` задай `yield_time_ms` в 20 000 мс. Если инструмент вернул ID сессии, дождись её завершения через `write_stdin` с тем же интервалом. Если нужно сохранить и сразу прочитать JSON, добавь `--output "$report" && cat -- "$report"` в ту же shell-команду. Сборщик пишет файл атомарно, а `&&` сохраняет код ошибки и читает файл только при успешном сборе. С `--strict` неполный JSON записывается до выхода с кодом 2. Чтобы получить его сразу вместе с кодом выхода, оставь вывод в stdout.

Для недели по названным проектам сразу запусти команду из таблицы. Сборщик сам разрешает имена. Проверяй окружение при ошибке сбора. Компактный отчёт читай одним выводом с `max_output_tokens=10000`. В корне находятся `diagnostics` и `week`. В `week` рядом с `counts`, `effective_projects` и `focus` лежат группы задач с описаниями, комментариями и ссылками. Если вывод усечён, выбери нужные поля всех групп из сохранённого JSON одним чтением.

Один `digest` загружает общий снимок задач, комментариев и фокуса для всех запрошенных периодов. Неделя начинается в понедельник. Текущий период заканчивается в момент сбора, `partial_day` указывает на незавершившийся день. Привычки входят в дайджест по просьбе пользователя. Их окно заканчивается с последним периодом отчёта, максимум по вчера включительно.

**Охват проектов.** Общий отчёт включает все доступные проекты и Inbox. При двух периодах рабочий фильтр применяется к неделе, день остаётся общим. Для названных проектов достаточно `--projects` с ID или уникальными именами через запятую. Можно опустить ведущие эмодзи. При неоднозначности сборщик перечислит кандидатов с ID. Для запроса именно на настроенный набор используй `--require-work-config`. Если `TICKTICK_SUMMARY_PROJECTS` пуст, объясни, почему этот период недоступен, и покажи остальные запрошенные части. Для обычной просьбы о рабочем саммари используй `--work`. Он допускает встроенный Work при отсутствии настройки. Назови фактические проекты из `effective_projects` и источник выбора, особенно при `work_selection_source=default`.

## Задачи и фокус

Для обычного отчёта используй компактный формат по умолчанию у `digest` и `habits`, в том числе при сохранении JSON через `--output /путь/report.json`. Выбери `--format full` при сборе, если запрос требует проверить причины исторических отмен, уточнить оговорки по полным описаниям и комментариям или разобрать исходные отметки привычек.

Для исторического дня с проверкой причин отмен прочитай полный отчёт одним выводом с `max_output_tokens=12000`. В корне находятся `diagnostics` и `day`. В `day` доступны `counts`, `focus.seconds`, `projects[].focus_seconds` и списки задач. Если вывод усечён, за одно чтение сохранённого снимка выбери сводку дня и полные карточки из `day.abandoned`. Ссылки бери из описаний и комментариев в снимке. Для карточки без ссылки достаточно её названия.

Сформулируй итоги по данным одного запуска. Объединяй связанные задачи, сохраняй ссылки и конкретные оговорки. Покажи общий фокус, разбивку по проектам и время упомянутых задач. В компактном JSON для этого есть `focus.human`, в полном — секунды. Время задач уже входит во время проектов. В общем итоге учитывается и фокус без проекта.

- `completed` подтверждает закрытие в TickTick. Опиши результат в пределах названия, описания и свидетельств. Сохрани оставшиеся шаги и блокеры. Если в последнем свидетельстве остаётся блокер, укажи, что карточка закрыта, а достижение цели требует подтверждения. Для утверждения об успешной публикации или настройке найди подтверждение результата в карточке.
- `open` показывает прогресс по комментариям, созданным или изменённым за период. Задача могла закрыться в другую дату.
- `abandoned` показывает кандидатов. Приводи причину, только если она подтверждена текстом и в период попадает отмена или свидетельство о её причине. Укажи дату события и дату пояснения, если они различаются. Когда видна только отмена, укажи, что причина неизвестна.
- `focus_only` подтверждает зарегистрированную активность. Результат работы требует отдельного свидетельства.

При проверке причины прочитай полное `description` и `comments` кандидата, а также `earlier_comments` с более ранним контекстом. Сверь дату события (`abandoned_at` или `completed_at`) с датами создания и редакции записи задачи или комментария (`created_at`, `modified_at`). `edited_after_period` отмечает текст текущего снимка с более поздней редакцией. Привязывай его содержание к исторической дате только при отдельном подтверждении. Компактный формат ограничивает цитаты, сворачивает вложения и длинные ссылки. `omitted_comments` показывает число скрытых комментариев.

Когда нужны и краткий обзор, и полные тексты, сохрани один полный отчёт с `--format full --output /путь/report.json`. Команда `render --input /путь/report.json` выдаёт компактный обзор, а `render --input /путь/report.json --task-id ID` показывает полные сведения о задаче из снимка. Обе команды работают локально. Для полного текста или исходных отметок нужен снимок, сохранённый в `full`.

## Привычки

У отдельного `habits` окно по умолчанию — 14 дней по вчера включительно. Для последних 30 дней передай `--habit-days 30`, для точного диапазона — `habits YYYY-MM-DD --habit-from YYYY-MM-DD` (конец, затем начало, обе даты включены). Для названных привычек передай `--habit` с ID или уникальным именем, повторяя флаг для нескольких. Исходные отметки доступны через `--format full`.

В компактном `habits` суммы за период находятся в `totals`, суммы и даты окон — в `split_by_week`, список привычек с их метриками — в `habits[]`. В `digest` те же поля находятся в `habits.totals`, `habits.split_by_week` и `habits.habits[]`. Массивы `weekly` в каждой записи списка следуют порядку окон в `split_by_week`. По умолчанию окна состоят из семи дней от начала периода. Для календарных недель отдельного отчёта `habits` передай `--week-start monday`. Сравнивай окна с учётом их длины и помечай сегодняшний день как предварительный. Дай посильный следующий шаг, если он следует из отметок.

Сборщик восстанавливает расписание привычек из текущего списка Open API по правилу DAILY/WEEKLY и исключениям. За начало он берёт `targetStartDate` с учётом более ранних доступных отметок, а при отсутствии этого поля использует дату создания. Для архивированной привычки (`status=1`) последний день включён. У активной (`status=0`) расписание открыто даже при заполненном `archivedTime`. Эти статусы относятся к самой привычке. История изменений правил и более ранние отметки за пределами запроса могут быть недоступны. Долю называй долей подтверждённых достижений по восстановленному расписанию. При `scheduled=null` укажи причину из `schedule_reason` и динамику `confirmed_achievements`. `off_schedule_achievements` считает достижения вне расписания только по привычкам с известным расписанием.

Статусы отметок не задокументированы. Сборщик считает достижением `status=0` или `2` при `value >= goal > 0`, частичным выполнением — `status=0` при `0 < value < goal`. Остальные сочетания входят в `unknown`. Пропуск по расписанию (`missed`) — завершившийся запланированный день без отметки. При наличии зарегистрированного фокуса по привычке покажи время.

## Доступность данных

Проверь статус запрошенных источников в `diagnostics.sources` и предупреждения. При частичной истории, активных задачах или комментариях перечисли подтверждённое и обозначь пробел. При неполном фокусе или отметках пустой результат и ноль не подтверждают отсутствие активности. Для автоматической публикации `--strict` сохраняет доступный JSON и возвращает ненулевой код, если обязательные данные неполны.

Кэш задач и комментариев общий для запусков CLI. Для изолированной сессии задай `--cache-dir <отдельный каталог>` или `TICKTICK_CACHE_DIR`. Это сохраняет штатные пути авторизации. Обычный запуск использует настроенный кэш и может перейти на временный, если каталог недоступен.

Сборщик ищет `ticktick` в репозитории навыка, затем в PATH. При ошибке совместимости обнови бинарник через `make build` в ticktick-cli или укажи `--cli` / `TICKTICK_CLI`. Для диагностики есть `doctor` с версией, доступом к проектам и источником рабочего набора. Open API читает токен из окружения, dotenv или конфигурации TickTick, web API — cookie из окружения или ~/.env. Для общего dotenv используй `--env-file`. Обе учётные записи должны совпадать.
