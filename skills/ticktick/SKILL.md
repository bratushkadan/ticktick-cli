# TickTick CLI

Используй `ticktick` для запросов к аккаунту. Добавляй `--json` для обработки результатов. Проверяй флаги через `ticktick <команда> --help`. Если бинарник из `PATH` без `v3 active --cache-ids` или `task comments-batch --use-cache`, собери свежий из checkout `ticktick-cli` командой `go build -o ticktick ./cmd/ticktick` и используй `./ticktick`.

- Команды `task`, `project`, `focus`, `habit` и другие команды Open API используют токен. CLI ищет его в `--token`, затем в `TICKTICK_TOKEN` или `TICKTICK_MCP_TOKEN` из окружения, затем в `--env-file` (по умолчанию `~/.config/ticktick/.env`), затем в `~/.config/ticktick/token`.
- Команды `v2` и `v3` используют `TICKTICK_V2_API_COOKIE` из окружения, затем из `--env-file` (по умолчанию `~/.env`). Используй настроенные учётные данные, не выводя их в логи или ответ. Для работы с кэшем задач и комментариев используй cookie и токен одного аккаунта.

## Точечные операции

- Найди исходные ID через `project list --json`, `task search "$QUERY" --json` или кэш. Для чтения известной задачи используй `task get "$TASK_ID" --project "$PROJECT_ID" --json`. Проверь совпадение по названию и списку перед изменением.
- Для создания используй `task create --project "$PROJECT_ID" --title "$TITLE"`. Для правок используй `task update "$TASK_ID" --project "$PROJECT_ID"` с нужными флагами. Для завершения используй `task complete "$TASK_ID" --project "$PROJECT_ID"`, для пачки до 50 задач есть `task complete-many --ids "$IDS" --project "$PROJECT_ID"`.
- Для добавления комментария используй `task comment-add "$TASK_ID" --project "$PROJECT_ID" --text "$COMMENT"`. Для просмотра фокуса и привычек доступны `focus list`, `habit list` и `habit checkins`. Синтаксис диапазонов смотри в `--help` конкретной команды.

Для JSON задач используй `status_slug`: `abandoned` (−1), `open` (0), `completed` (2). Значение `1` означает `completed_subtask` внутри `items[]`; у самой задачи оно остаётся `unknown`. Исходный `status` доступен для диагностики. Эти значения относятся к задачам и элементам чек-листа.

## Активные и завершённые задачи

```bash
ticktick v3 active --cache-ids --json
ticktick v2 completed --limit 2000 --cache-ids --json
```

- `v3 active` одним запросом к `/api/v3/batch/check/0` загружает и сохраняет активные задачи. Инкрементальный checkpoint доступен в Go-клиенте `BatchCheck`, CLI выполняет полную загрузку.
- `v2 completed` загружает страницу истории по `completedTime`. По умолчанию используется `completedInAll/`, для одного списка передай `--project "$PROJECT_ID"`. Для истории в заданном диапазоне передай `--from` и `--to` с явным смещением часового пояса. Для следующей страницы используй `nextTo` ответа как `--to`, сохраняя остальные параметры. Удаляй дубликаты по ID и проверяй продвижение курсора. Если граница повторяется, проверь полноту выборки, увеличив страницу или запросив нужные списки отдельно.
- Для поиска недавно изменённых старых задач освежи `v2 completed` за весь нужный горизонт завершения, например за полгода, затем фильтруй записи по `payload.modifiedTime`. Время изменения помогает обнаружить более поздний комментарий или другую правку. Для подтверждения события сверяй содержимое и время самого комментария. `metadata.updatedAt` показывает время записи в локальный кэш.

Эти команды записывают исходные данные в `~/.config/ticktick/cache/cache.json`. По умолчанию вывод содержит псевдонимы `anon-…`. С `--cache-ids --json` поле `id` в ответе содержит исходный ID задачи для поиска в `tasks[taskId].payload`. Бери из `payload` название, текст, исходный `projectId`, `modifiedTime` и `commentCount`. Кэш объединяет страницы и запуски по ID. Используй ID из ответов текущей загрузки для отбора её записей. Держи подробное содержимое кэша локально и выводи только данные, необходимые для задачи.

## Чтение комментариев

Используй `payload.commentCount` из свежей записи задачи. Положительное значение помечает задачи с комментариями, явный ноль позволяет пропустить запрос. Если поле отсутствует и список комментариев нужен, проверь его через CLI.

```bash
ticktick task comments-batch --tasks "$PROJECT_ID:$TASK_ID" --use-cache --json
```

- Для нескольких задач передай пары `PROJECT_ID:TASK_ID` через запятую. Для задач одного списка можно передать `--project "$PROJECT_ID" --ids "$IDS"` вместо `--tasks`.
- `--use-cache` возвращает свежие списки из кэша и запрашивает недостающие, устаревшие или инвалидированные. Команда также пытается освежить списки текущего аккаунта старше 24 часов. Изменение `modifiedTime`, `commentCount` или `projectId` при загрузке задачи, равно как успешное добавление или удаление комментария через CLI, инвалидирует сохранённый список.
- JSON имеет форму `{taskId: [comments]}`. `[]` означает пустой список, а отсутствующий ключ в частичном результате указывает на ошибку чтения. При частичном сбое CLI печатает успешные результаты в stdout, ошибки в stderr и возвращает ненулевой код. `createdTime` и `modifiedTime` комментария представлены в миллисекундах Unix.
- Ранее сохранённые списки лежат в `comments[taskId].payload`, где `null` помечает список к обновлению. Для чтения с автоматической проверкой свежести используй `--use-cache`. Одиночная команда `task comments` всегда обращается напрямую к API.
